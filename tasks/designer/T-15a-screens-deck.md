# T-15a. Экраны «Колода» и «Шаблон» (рабочий прототип)

Модель: sonnet. Волна 5. Зависит от слитых T-12, T-13.

Это рабочий прототип экранов, чтобы сервисом можно было пользоваться и показать его на видео. Бриф и макет по правилам владельца для интерфейсов идут следом; состав экрана взят из `docs/design/ui-requirements.md`, от него не отходить.

## Цель

Автор презентации открывает страницу, загружает pptx, пишет бриф и через несколько минут листает три варианта презентации, видит находки аудита на слайде, чинит отмеченные и скачивает pptx, HTML и PDF. На странице «Шаблон» он видит, как сервис понял его файл.

## Файлы

Только эти файлы, других не трогать:

- `frontend/src/designer/api.ts`, `DeckPage.tsx`, `TemplatePage.tsx`, `SlideFrame.tsx`, `deck.css` (новые)
- `frontend/src/designer/api.test.ts` (новый)

Маршруты уже заведены в `frontend/src/router.tsx`: страницы подключаются оттуда, сам файл не менять. Стиль бери из `frontend/src/style.css` (переменные цвета, кнопки, шрифты), новые цвета не вводить.

## Что сделать

1. `api.ts`: клиент сервиса `designer`. Адрес из `import.meta.env.VITE_DESIGNER_URL`, по умолчанию `http://localhost:8090`. Методы под пути из `designer/src/designer/api/app.py`: список и загрузка шаблонов, манифест, запуск колоды с вариантами, поток событий (`EventSource`), состояние колоды, контекстный аудит варианта, починка выбранных находок, адреса файлов, карточка прогона. Типы ответа сверить с `api/schemas.py`.
2. `SlideFrame.tsx`: один слайд в контейнере с пропорцией слайда. Основной вид это картинка слайда по адресу `GET /decks/{id}/{variant}/slides/{n}.png` (его пишет параллельная задача T-26; адреса картинок придут в состоянии колоды, поле назови `slide_images` и прими, что его может не быть). Нет картинки: слайд показывается запасной вёрсткой из сцены (элементы сцены абсолютными блоками в процентах, текст настоящим текстом). Поверх слайда слой меток находок.
3. `DeckPage.tsx`, состав строго по требованиям:
   - слева узкая колонка: выбранный шаблон (имя, смена по клику, загрузка нового pptx), бриф, назначение, аудитория, число слайдов, запуск;
   - в центре крупный текущий слайд; над ним переключатель вариантов из трёх сегментов, отличие варианта в подсказке сегмента; под ним лента миниатюр, у миниатюры с находками отметка с числом;
   - находки текущего слайда метками на слайде (по `box` находки) и панелью справа с отметками «исправить» и «отклонить», вид находки (детерминированная или по смыслу) значком с подсказкой; кнопка починки отправляет отмеченные и показывает отчёт «что изменено»;
   - пока идёт генерация, на месте слайда шаги хода работы, миниатюры появляются по мере готовности;
   - справа вверху значки скачивания pptx, HTML, PDF и значок карточки прогона (модель, скиллы с версиями, время шагов);
   - состояния: пусто (нет шаблона: одно действие «загрузить pptx»), загрузка, ошибка понятным текстом, заполнено.
4. `TemplatePage.tsx`: палитра с ролями, шрифты, шкала кеглей, сетка слайдов-образцов с типом и назначением (`purpose`), отметка у образцов, которые сервис не берёт (`needs_images`), с причиной в подсказке.
5. Значки из `lucide-react`, подписи кнопок одним словом, пояснения в подсказках (`title` и `aria-label`), без абзацев-объяснений в теле экрана, без марки и версии в углах.

## Готовность

Из каталога `frontend`: `npm ci`, затем `npm run build` и `npm test`. Сборка без ошибок типов. `api.test.ts` проверяет сборку адресов, разбор событий и отправку починки на подменённом `fetch`.
