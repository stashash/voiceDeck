# Приёмка этапа 2: пакет данных, аналитические слайды и брендбук

Ветка `stas_last`. Реализован локальный путь от нескольких файлов через выбор смыслового представления к существующей генерации презентации. Пользовательские изменения в `Main.java`, `compose.public-demo.yaml`, `frontend/src/stage/useSession.ts`, `frontend/tsconfig.tsbuildinfo`, `.serena`, `designer/uv.lock` и `frontend/src/designer/api.ts` (base URL) отделены от изменений этой задачи.

## Пользовательский путь

1. На главной открыть «Раскрыть смысл данных», добавить 1–7 CSV/XLSX/JSON/TXT/Markdown файлов и сформулировать цель: например, «показать динамику» или «сравнить план и факт».
2. Для каждой найденной таблицы изучить роли полей, типы, пропуски и предупреждения; выбрать один из объяснимых вариантов и включить/исключить эту таблицу. Выбор помнит вкладки текущей страницы.
3. Выбрать дизайн-систему и агента, затем передать все выбранные таблицы одной презентацией в существующий `/decks` генератор. Неподдерживаемый вариант не проходит незаметно: он не может быть включён в сборку.
4. Для шаблона открыть «Дизайн-системы», выбрать систему и добавить JSON в разделе «Брендбук и токены». По умолчанию выше приоритет у брендбука; приоритет можно переключить на шаблон, затем удалить брендбук с восстановлением исходных токенов.

## Пакет и lineage

- `POST /insights/plan`: 1–7 файлов, до 1 МиБ каждый; максимум 21 таблица. Возвращает `id` пакета, стабильный `dataset_id`, исходный SHA-256, профиль и ранжированный план.
- `GET /insights/plan/{id}` восстанавливает сохранённое содержимое серверного пакета. Исходные байты, нормализованные строки и hash хранятся в локальном `DESIGNER_DATA_DIR`.
- `POST /insights/plan/materialize-bundle`: form-поля `bundle_id`, `selections` — JSON-массив `[{"dataset_id":"…","candidate_kind":"line","required_fields":["period","revenue_usd"]}]`. Маршрут сверяет хэш, заново вычисляет план и отклоняет чужие/повторные таблицы и поддельные поля.
- Выбранные подсказки приводят к обычному `insights_id`, который подхватывается `/decks`. Снимок источника и `DataProvenance` доходят до плана слайда и `deck.json`: raw/content hash, лист/индекс, колонки, исходные/исключённые/показанные строки, формула, единица, знаменатель, missing policy, предупреждения и страница справочника.
- На аналитическом слайде и в notes/PPTX/HTML/PDF видны имя источника и охват. Проверено реальным PowerPoint → PDF/PNG для временного ряда.
- Таблица более 20 строк в пакетном пути разбивается на страницы по 20 строк. Страница имеет собственный lineage и явный интервал; данные не теряются молча. Максимум 20 страниц на таблицу и 60 слайдов за одну сборку. Больший справочник требует фильтрации и получает понятную ошибку.

## Типы представления

- Динамика, столбцы/полосы, доли pie, histogram, справочная таблица и подсчёт числа исходных строк.
- Scatter требует две числовые серии, полные пары, конечные координаты X/Y; корреляция не вычисляется, причинность не заявляется.
- Grouped-column сравнивает несколько рядов по общим категориям и не складывает значения.
- Stacked-column предлагается только при явном запросе на накопление, с 2–5 мерами, одинаковыми явно указанными единицами, уникальными категориями и неотрицательными значениями. Аддитивность не выводится автоматически; предупреждение остаётся.
- Новые scatter/grouped/stacked типы проверены через SVG-геометрию, native chart XML и roundtrip встроенной книги в PPTX. Живое преобразование этих новых типов конкретным установленным Office/LibreOffice не проверено; PDF-экспорт подтверждён для временного ряда.
- Локализованное слово «Основной» вместо чисел на оси было обнаружено по PNG и исправлено на явный числовой формат. Выручка получила понятный заголовок и USD-ось из явного суффикса поля.

## Брендбук JSON

Валидация разрешает цветовые роли, семейства шрифтов, шкалу размеров в pt, поля слайдов как доли и вложенный объект `tokens`. Вход ограничен 256 КиБ. Поля, значения и hex цвета проверяются; пути и файлы из JSON не читаются. Сохраняются имя исходного JSON, SHA-256 и исходные токены шаблона для переключения приоритета/сброса. Это импорт ограниченного JSON token schema.

PDF-руководство, Figma, папка с логотипами и примерами, автоматическая provenance по каждому индивидуальному значению токена и поиск/вставка внешних бренд-ассетов не реализованы. Пользователь может добавить логотип или изображение прежними средствами, но это не является импортом брендбука.

## Выполненная проверка

- Полный backend-набор в актуальном рабочем дереве: **1244 теста собрано, завершился без ошибок** (в наборе есть штатные skips); повторные фокусные проверки provenance, planner, графиков и brandbook также прошли.
- Расширенный тестовый набор Astra для графиков: **361 passed, 8 skipped**. Skips включают отсутствующие пользовательские PPTX/движок. Он проверяет backend, экспортеры и контракты, но не заменяет реальное Office-преобразование.
- После добавления панели brandbook полный frontend-набор повторно прошёл: **656 passed, 18 skipped**; TypeScript check и production build прошли.
- В настоящем браузере проверены UI «Брендбук и токены» на странице дизайн-системы и — в отдельном изолированном браузере — загрузка двух CSV, план обеих таблиц, смена варианта, исключение таблицы и сохранение состояния между вкладками до закрытия страницы. После полной перезагрузки UI не восстанавливает пакет и выбор, хотя сохранённый пакет остаётся доступен через API.
- Реальный PowerPoint создал [source-coverage.pptx](../artifacts/stage2-provenance/source-coverage.pptx); его PDF и PNG видны среди [проверенных артефактов](../artifacts/stage2-provenance/). Browser proof: [bundle-ui.jpg](../artifacts/stage2-provenance/bundle-ui.jpg).
- `/decks` handoff для нескольких источников был проверен тестом с подменой генератора. Реальный запрос к локальной LLM и результат полной брендированной колоды в браузере не проверялись из-за отсутствия настроенного агента и дизайн-системы в изолированном браузерном хранилище.

## Остаточные ограничения

1. Пользовательский пакет можно запросить по id через API, но UI не показывает историю/восстановление и выбор не переживает полную перезагрузку.
2. Полноценное создание презентации требует подключённой локальной модели/агента и выбранной дизайн-системы; данный сквозной LLM вызов не подтверждён.
3. Автоматический разбор PDF/Figma и каталога брендбука не реализован. JSON токены работают.
4. Grouped и source-footer на произвольных плотных/групповых пользовательских макетах ещё нуждаются в проверке на их образцах.
5. Новые типы прошли XML/geometry-тесты, но их реальный Office/LibreOffice-to-PDF результат пока не проверялся.
6. Полный демонстрационный скринкаст до 5 минут не записан. Нужны настроенные агент и образец брендбука, прежде чем такой сценарий будет честно демонстрировать готовый LLM-результат.
7. Dark Factory Astra-провайдер в этом окружении ранее вернул HTTP 403; сложная реализация сделана native Astra и обычные bounded файлы — Luna. Успешного DF прогона нет.
