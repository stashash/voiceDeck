# Live-редактор VoiceDeck: полная инструкция и архитектура

Этот документ описывает рабочий режим голосового редактирования презентации: как им пользоваться, какие команды поддерживаются, как устроен контур речи, как обеспечивается точность изменений и какие решения нужны для дальнейшего ускорения.

## 1. Назначение режима

Live-редактор предназначен для работы с презентацией во время разговора. Пользователь говорит, а система:

1. получает окончательную фразу от распознавания речи;
2. определяет, является ли она содержимым слайда или командой;
3. выбирает слайд и компоненты;
4. применяет одно атомарное изменение;
5. показывает результат на холсте;
6. при явной команде публикует снимок слайда в окно для зрителей.

Редактор работает с документом презентации, а не с изображением экрана. Поэтому заголовок, карточка, таблица, диаграмма и изображение остаются отдельными редактируемыми объектами.

Открытие: `http://localhost:8088/#/live`.

## 2. Режимы работы

### Управляю слайдом

Это основной режим. Свободная фраза считается инструкцией для изменения документа и отправляется в планировщик, если она не совпала с локальной быстрой командой.

Примеры:

```text
Создай заголовок «План запуска» и три карточки: Продукт, Маркетинг, Продажи.
Сделай карточку Маркетинг фиолетовой.
Перенеси выбранную карточку на второй слайд.
Добавь таблицу продаж за три месяца.
```

Префикс `Команда` необязателен в этом режиме.

### Диктую текст

Фраза добавляется в выбранный заголовок, текстовый блок или карточку. Если подходящего объекта нет, создаётся текстовый блок.

```text
Диктую текст.
Рост продаж в третьем квартале составил 24 процента.
```

Чтобы выполнить команду, не добавляя её на слайд, используйте префикс:

```text
Команда: выбери номер два.
Команда: сделай текст жирным.
```

Режим можно переключать голосом: `Управляю слайдом`, `Диктую текст`.

## 3. Жизненный цикл голосовой фразы

Распознавание разделяет речь на промежуточный текст и окончательные фразы. Только окончательная фраза изменяет документ. Это предотвращает ситуацию, когда недоговорённое предложение успевает создать компонент.

После получения окончательной фразы порядок обработки такой:

1. нормализация регистра, пунктуации и префикса `Команда`;
2. переключение режима или диктовка;
3. локальные команды без модели;
4. поиск изображения и выбор результата;
5. отмена, возврат и публикация;
6. запрос плана у локальной модели;
7. проверка схемы плана;
8. атомарное применение операций;
9. сохранение документа в браузере.

Длинные свободные запросы не должны становиться текстом слайда при ошибке модели. Если модель недоступна или не поняла инструкцию, редактор показывает ошибку или задаёт уточняющий вопрос.

## 4. Быстрые команды без модели

Эти действия исполняются сразу и не ждут Ollama.

### Номера объектов

У каждого компонента есть постоянный номер внутри текущего слайда. Номер сохраняется при перестановке слоёв и не попадает в экспорт или окно для зрителей.

```text
Покажи номера.
Скрой номера.
Выбери номер семь.
Выбери номера два и три.
Выбери все элементы.
Сними выделение.
```

Номер надёжнее описания вроде «вторая карточка»: он однозначен даже при одинаковом тексте.

### Выбор по смыслу

Также можно назвать точный текст компонента:

```text
Выбери карточку «Продажи».
Выбери заголовок «План запуска».
```

Если найдено несколько одинаковых компонентов, редактор не угадывает и просит назвать номер.

```text
Выбери две карточки.
```

Такая команда выполняется автоматически, если на слайде ровно две карточки. При трёх и более карточках нужно сказать:

```text
Выбери номера два и четыре.
```

### Перемещение

```text
Вправо на двадцать.
Влево на 40 пикселей.
Вверх на десять.
Сдвинь выбранные вниз на 30 пикселей.
```

Если расстояние не названо, используется 20 пикселей. Группа перемещается единым смещением, поэтому расстояния между её объектами сохраняются. Координаты ограничиваются границами холста 1280×720.

### Контекстные поправки

После перемещения можно продолжить короткой фразой:

```text
Ещё.
Ещё немного.
Половину назад.
```

`Ещё` повторяет последний сдвиг, `Ещё немного` применяет половину последнего сдвига, `Половину назад` возвращает половину. Если документ изменился после перемещения, редактор не применяет устаревшую поправку и просит повторить направление.

### Удаление, копирование и история

```text
Удали выбранное.
Дублируй выбранные.
Отмени.
Верни.
```

Каждая сложная просьба применяется одним атомарным изменением. Ошибка в середине плана откатывает весь план. Одна команда `Отмени` отменяет последний содержательный шаг.

## 5. Компоненты слайда

Поддерживаются следующие типы:

| Тип | Назначение |
|---|---|
| Заголовок | Главная мысль слайда |
| Текст | Абзац или пункт |
| Карточка | Смысловой блок с фоном |
| Фигура | Декоративный или выделяющий элемент |
| Изображение | Локальный или найденный визуальный материал |
| Таблица | Структурированные строки и столбцы |
| Диаграмма | Подписи и неотрицательные значения |

Создание:

```text
Добавь заголовок «Результаты квартала».
Добавь текст «Ключевой вывод».
Создай три карточки: Продукт, Маркетинг, Продажи.
Добавь фигуру справа.
```

Редактирование свойств:

```text
Сделай ширину 540 и высоту 300.
Поставь слева 64, сверху 180.
Размер текста 32.
Сделай текст белым и жирным.
Выровняй по центру.
Скругление 20.
Поверни на 10 градусов.
Сделай прозрачность 70 процентов.
```

`move` использует смещение, например `на 30 вправо`. `update` использует абсолютные координаты, например `слева 64`.

## 6. Выравнивание, группы и слои

```text
Сгруппируй номера два и три.
Разгруппируй выбранное.
Выровняй карточки по верхнему краю.
Выровняй выбранное по центру слайда.
Распредели карточки по горизонтали.
Отправь фигуру на задний план.
Подними карточку на один слой.
```

Распределение требует минимум трёх объектов. Для группы перемещение и изменение позиции применяется ко всем членам группы.

## 7. Таблицы и диаграммы

Таблица хранится как массив строк. При изменении одной ячейки модель должна вернуть всю таблицу с сохранением остальных значений.

```text
Добавь таблицу: Товар, Цена; Книга, 500; Ручка, 100.
В таблице измени цену книги на 900.
Добавь строку «Карандаш, 50».
```

Диаграмма хранит отдельно подписи и значения:

```text
Добавь столбчатую диаграмму: Январь 10, Февраль 20, Март 15.
Измени значение марта на 18.
```

Значения диаграммы не должны выдумываться моделью. Если данных не хватает, редактор должен спросить пользователя.

Ограничения: до 20 строк и 12 столбцов в таблице; до 20 значений в диаграмме.

## 8. Слайды

```text
Создай новый слайд.
Выбери второй слайд.
Дублируй первый слайд.
Перемести текущий слайд на третье место.
Перенеси выбранные объекты на второй слайд.
Удали третий слайд.
```

Перед изменением другого слайда лучше явно сказать `Выбери второй слайд`. После перехода выделение сбрасывается, чтобы команда не изменила объект по ошибке на новом слайде.

Лимиты редактора: до 100 слайдов и до 100 объектов на слайде.

## 9. Дизайн-система

Выбранная дизайн-система задаёт:

- фон и палитру;
- шрифты;
- размеры заголовков и основного текста;
- поверхности карточек;
- композиции и слоты макета;
- базовые правила контраста.

Новые объекты используют тему. Для существующих объектов тема применяется при выборе дизайн-системы. После ручной правки конкретное свойство сохраняется и не перезаписывается повторной загрузкой документа.

Примеры:

```text
Примени композицию для трёх карточек.
Используй основной цвет темы для заголовка.
Перестрой карточки по выбранному макету.
```

Если цвет текста и фон дают плохой контраст, редактор подбирает безопасный цвет автоматически.

## 10. Изображения

Поиск в интернете:

```text
Найди фотографию курьера.
Подбери изображение гор.
Ещё варианты.
Возьми вторую.
```

Поиск использует Wikimedia Commons. Для каждого результата сохраняются URL источника, автор и лицензия. Перед публикацией презентации нужно проверить условия лицензии выбранного изображения.

Загрузка файла доступна через панель изображения.

Генерация изображения поддерживается через совместимый с Automatic1111 API. Для включения нужно задать:

```text
DESIGNER_IMAGE_URL=http://адрес-сервера:7860
```

Если переменная не задана, кнопка генерации остаётся отключённой. Ollama сама по себе не является генератором изображений.

## 11. Окно для зрителей

Редакторский холст и окно для зрителей разделены. Правки видны на холсте сразу, но зритель видит только опубликованный снимок.

```text
Покажи залу.
```

После публикации последующие изменения не меняют уже показанный снимок. Это позволяет спокойно подготовить следующий вариант и опубликовать его только после проверки.

Клавиша пробела фиксирует черновик, Backspace убирает текущий опубликованный слайд. Эти действия сохраняют редактируемый документ.

## 12. Архитектурное решение

### Состояние документа

Документ состоит из массива слайдов. Слайд содержит фон и компоненты. Компонент имеет стабильный UUID, номер для речи, тип, текст, геометрию, стиль и дополнительные данные таблицы или диаграммы.

Выделение хранится как основной объект и массив выбранных объектов. Старые действия, которым нужен один объект, используют основной объект; голосовые операции над `выбранными` используют весь массив.

### Два контура команд

Первый контур — детерминированный:

- номера и выбор;
- перемещение;
- повтор относительного движения;
- удаление, дублирование, отмена;
- переключение режима.

Он не использует модель и должен укладываться в десятки миллисекунд.

Второй контур — планировщик:

- свободное создание слайда;
- редактура текста и содержания;
- таблицы и диаграммы;
- композиция;
- сложные ссылки на объекты.

Планировщик возвращает только JSON-операции. Код проверяет операции, ограничения и координаты; код, сгенерированный моделью, никогда не исполняется.

### Атомарность

Перед планом сохраняется снимок документа. Если любая операция не прошла проверку, документ и история возвращаются к исходному снимку. Это защищает от частично применённых команд.

### Уточнения

Если объект не определён однозначно, модель возвращает короткий вопрос вместо операции. Ответ пользователя добавляется к предыдущему запросу только в рамках текущего незавершённого уточнения.

## 13. Локальная модель и задержка

По умолчанию используется Ollama:

```text
DESIGNER_EDITOR_LLM_URL=http://host.docker.internal:11434/v1
DESIGNER_EDITOR_LLM_MODEL=qwen3.8:27b
```

Для ускорения:

1. прогрейте модель одним коротким запросом после запуска;
2. точные команды формулируйте через номера и направления;
3. не передавайте в модель ненужные слайды и большие таблицы;
4. для обычных правок отключайте рассуждение;
5. используйте большую модель только для свободного содержания и композиции;
6. не отправляйте новую команду, пока пользовательская фраза ещё является промежуточным текстом.

Практическая архитектура для следующей версии:

```text
микрофон → локальный VAD/ASR → классификатор команды
                         ├─ точная команда → код редактора
                         ├─ выбор объекта → Jev/Choice или локальный классификатор
                         └─ свободное содержание → Qwen с JSON-схемой
```

Jev полезен как быстрый классификатор закрытого набора: действие, объект, направление, цвет, слой. Он не должен вычислять координаты, генерировать длинный текст или заменять редакторскую валидацию. Для полностью локального режима роль Jev может выполнять маленькая локальная модель или набор правил.

## 14. Надёжность и безопасность

- Текст объектов считается данными, а не инструкциями для модели.
- Модель не получает право выполнять код.
- Операции ограничены белым списком.
- Числа, цвета, размеры, количество строк и границы холста проверяются в коде.
- Сложные изменения имеют одну точку отмены.
- Устаревший ответ модели отбрасывается, если документ изменился во время ожидания.
- Сетевые изображения принимаются только по разрешённым HTTPS-хостам Wikimedia.
- Автор и лицензия изображения сохраняются в заметках экспорта.
- Автосохранение выполняется в localStorage браузера; JSON-экспорт нужен для резервной копии.

## 15. Экспорт и ограничения текущей версии

Доступны HTML-презентация и JSON-исходник. HTML можно открыть в браузере или распечатать. PPTX-экспорт пока не реализован. Для внешних изображений при показе требуется интернет-соединение.

Генератор изображений не включён по умолчанию. Реальный микрофон требует разрешения браузера и не заменяется текстовым полем в автоматических тестах.

## 16. Проверка перед использованием

Перед демонстрацией:

1. откройте `/settings` и убедитесь, что Ollama показывает модель;
2. выберите модель для Live-режима;
3. откройте `/live` и выберите дизайн-систему;
4. проверьте короткую команду: `Покажи номера`;
5. выберите два объекта и проверьте `Вправо на 20`;
6. проверьте `Отмени`;
7. включите микрофон и скажите одну фразу с паузой;
8. нажмите `Покажи залу` только после проверки композиции.

Команды для ручного smoke-теста:

```text
Создай заголовок «План запуска».
Создай три карточки: Продукт, Маркетинг, Продажи.
Выбери номера два и три.
Вправо на 20.
Ещё немного.
Сделай выбранные карточки белыми.
Отмени.
Покажи залу.
```

Автоматические проверки frontend запускаются из `frontend`:

```powershell
npm test
npx tsc -b
```

Интеграционный прогон с реальной Ollama-моделью:

```powershell
$env:RUN_EDITOR_LIVE='1'
npx vitest run src/stage/editorLive.test.ts
```

## 17. План развития

### Этап A: скорость

- разделить очередь быстрых и модельных команд;
- добавить отмену текущего HTTP-запроса голосом `Стоп`;
- отключить reasoning для операций, где нужен только JSON-план;
- отправлять в модель только текущий слайд и связанные объекты;
- прогревать Ollama при старте.

### Этап B: точность

- расширить локальный словарь русских формулировок;
- хранить последнюю операцию и её цель как контекст диалога;
- добавить подтверждение для массового удаления и больших перестроений;
- вести журнал команды, выбранных объектов, результата и времени.

### Этап C: полноценное создание презентации

- добавить отношения между объектами: «под заголовком», «между карточками», «по сетке»;
- сделать ограничения композиции, чтобы ручное перемещение не ломало макет;
- добавить редактирование диаграмм и таблиц по строкам и столбцам;
- подключить генератор изображений;
- реализовать PPTX-экспорт с сохранением объектов.

### Этап D: оценка качества

Нужен набор русских команд с ожидаемым финальным документом. Для каждой команды сравниваются не слова ответа модели, а состояние презентации: типы объектов, текст, координаты, стиль, количество слайдов и отсутствие лишних объектов. Отдельно измеряются время ASR, время маршрутизации, время модели и время применения операции.
