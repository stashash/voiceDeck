# T-04. Клиент модели, версии скиллов, план презентации по брифу

Модель: sonnet. Волна 1. Зависит только от `designer/src/designer/contracts.py`.

## Цель

Человек пишет бриф в три абзаца, называет назначение и аудиторию и получает план: сколько слайдов, в каком порядке, что на каждом. В карточке прогона видно, какой версией какого скилла план собран: поменяли промпт, и понятно, почему результат стал другим.

## Что сделать

1. `LlmClient`: `POST {base_url}/chat/completions` OpenAI-совместимого сервера через `httpx`. Ответ строго по JSON-схеме (`response_format` с `json_schema`, `strict: true`). Перед разбором убирать блок рассуждений `<think>…</think>`. При битом JSON или ответе не по схеме до двух повторов. Картинки передавать частями сообщения как `data:image/png;base64`. Адрес и модель по умолчанию из переменных `DESIGNER_LLM_URL` (`http://127.0.0.1:1234/v1`) и `DESIGNER_LLM_MODEL` (`qwen/qwen3.8-27b`). Клиент принимает необязательный `transport` для тестов и считает время каждого вызова.
2. Скиллы: папка `designer/skills/<имя>/` с `skill.yaml` (`name`, `version`, `temperature`, `max_tokens`) и `prompt.md` с подстановками `{{имя}}`. Незаполненная подстановка это ошибка. `sha256` считается по байтам обоих файлов. `Skill.ref()` возвращает `SkillRef`.
3. `run.py`: `RunRecorder` собирает `RunManifest`: модель, использованные скиллы с версией и хешем, времена этапов.
4. `make_plan`: схема ответа строится из `DeckPlan`. После ответа проверки кодом:
   - число слайдов: ровно столько, сколько задано; если не задано, от 10 до 15;
   - первый слайд `title`, последний `thanks` или `cta`;
   - каждое число на слайдах и в диаграммах есть в тексте брифа, иначе диаграмма или число убираются;
   - при нарушении один повтор с перечнем нарушений в сообщении.
5. Промпт `plan-deck` по-русски. В нём правила из ТЗ: заголовок слайда это вывод, а не тема; один слайд пересказывается одним предложением; факты и цифры только из брифа; порядок от общего к частному либо наоборот по характеру материала; типы слайдов только из перечисления `SlideKind`; числовые данные по возможности диаграммой или таблицей.

## Готовность

Из каталога `designer`:

```
python -m pytest tests/llm tests/plan
```

Живых вызовов модели в тестах нет, сервер подменяется через `httpx.MockTransport`. Тесты обязаны проверять: запрос содержит схему и текст промпта; блок `<think>` отрезается; повтор при битом JSON; картинка уходит как data URL; хеш скилла меняется при правке промпта; незаполненная подстановка даёт ошибку; план на 5 слайдов по просьбе «до 5 слайдов»; число, которого нет в брифе, в план не попадает.

## Запреты

- Промпты в код не зашивать, только файлами в `designer/skills`.
- Закрытые модели и облачные адреса по умолчанию не использовать.
- Полный набор тестов не гонять, только `tests/llm` и `tests/plan`.
