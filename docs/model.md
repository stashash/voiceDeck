# Модель voiceDeck: что есть в сервисе и как это связано

Снята с кода 2026-09-23 (`designer/src/designer/contracts.py`, `designer/src/designer/api/app.py`,
`designer/src/designer/pipeline.py`, `backend/src/main/java/local/voicedeck/Session.java`).
Строки с пометкой «по брифу» в коде пока нет: их вводит бриф `docs/design/brief-app.md`.

Подтверждено владельцем: состав экрана «Дизайн-система» 2026-09-23; карта приложения версии 2 2026-09-24, ответ «Да, этот состав», Live-режим на любом агенте, ответ «Любой агент на выбор». Остальное снято с кода, решения по умолчанию помечены «по умолчанию».

## Словарь: слово на экране и сущность в коде

| На экране | В коде |
|---|---|
| презентация | колода (`decks/<id>`) |
| вариант вёрстки | вариант колоды (`decks/<id>/<variant>`) |
| Live-режим | сессия сцены (`Session.java`) |
| слайд из речи | живой слайд (`POST /live/slide`) |
| агент | клиент модели (`llm/client.py`); CLI-агенты по брифу |

## Сущности

| Сущность | Что это | Откуда берётся | Где лежит |
|---|---|---|---|
| Дизайн-система | всё, что сервис понял из одного pptx: токены, образцы, картинки, макеты | автор загружает pptx, `POST /design-systems` | `data/design-systems/<id>/manifest.json` |
| Токены | цвета с ролями, шрифты, шкала кеглей, поля кадра, направляющие | разбор pptx, без модели | `DesignSystem.tokens`, `tokens.css` |
| Образец | слайд шаблона как заготовка вёрстки: тип, назначение, места под текст, повторяющиеся блоки | разбор pptx; назначение и «держится на фото» дописывает модель по картинке слайда | `DesignSystem.patterns` |
| Колода | презентация по брифу: план слайдов и три варианта вёрстки на одной системе | автор пишет бриф, `POST /decks` | `data/decks/<id>/` |
| Вариант колоды | одна вёрстка плана (a, b, c) с аудитом и файлами pptx, html, pdf | вёрстка по образцам | `data/decks/<id>/<variant>/` |
| Сессия сцены | выступление: речь режется на куски, из куска получается слайд | спикер на «Сцене», Java-сервис | в памяти Java-сервиса |
| Живой слайд | слайд из куска речи на образце выбранной системы | `POST /live/slide` | в памяти сессии |

## Поля дизайн-системы, которые видит человек

| Поле | Значение в коде | Замечание |
|---|---|---|
| Исходный файл | `source_file` | имя pptx |
| Размер кадра | `slide_size_emu` | 12192000×6858000 это 16:9 |
| Цвет | `hex`, `role` (background, surface, text, text_muted, accent, accent_alt, other), `share`, `source` (theme, usage) | на экране шесть ролей по одному цвету: с наибольшей долей среди `usage` (замер слайдов), цвет `theme` только если в замере роли нет; остальные цвета и все `other` в «ещё»: по брифу. `share` считается внутри своего источника, доли `usage` и `theme` не сравниваются |
| Шрифт | `family`, `role`, `embedded_file`; поля состояния нет, по брифу `embedded_state` | три состояния: встроен и извлечён (`embedded_file` есть); встроен, но не извлекается (сжат в EOT, `parse/assets.py`); в файле нет (`embedded_file` пуст) |
| Ступень кегля | `size_pt`, `role` (display, title, heading, body, caption) | |
| Поля | `left`, `top`, `right`, `bottom` в долях кадра | |
| Образец | `source_slide`, `kind`, `purpose`, `needs_images`, `theme`, `preview` | `preview` сейчас не заполняется: картинка образца по брифу |
| Имя системы | нет, есть только `id` из имени файла | по брифу |
| Предложение «не использовать» | `needs_images` | ставит модель по картинке образца |
| Решение автора «в вёрстке» | нет | по брифу: флажок у каждого образца. По умолчанию равен обратному предложению; автор снимает или возвращает, решение автора сильнее предложения и переживает повторное описание |
| Снятие подтверждено | нет | по брифу: отметка у системы. Пока её нет, над образцами полоса «Модель сняла N образцов» с действием «Подтвердить»; после подтверждения полоса уходит, флажки остаются |
| Описание пропущено | нет, сбой уходит только в журнал | по брифу: отметка у системы, по ней экран показывает ошибку и «Описать заново» |

## Ход создания

`pipeline.import_template`: разбор pptx (`build_package`: токены, картинки, шрифты, образцы) идёт без модели
за секунды; затем модель по картинке каждого образца пишет назначение (`_describe`, 1–2 минуты на 29 образцов).
Сбой модели импорт не роняет: образцы остаются без назначения. Ответ приходит одним куском после обоих шагов.
Показ по частям (сначала токены, потом образцы по одному) по брифу.

## Действия над системой

| Действие | Сейчас | По брифу |
|---|---|---|
| Создать из pptx | `POST /design-systems` | то же, ответ по частям |
| Переименовать | нет | поле `name` в манифесте |
| Снять или вернуть образец | нет | решение автора в манифесте |
| Подтвердить снятие моделью | нет | отметка «снятие подтверждено» в манифесте; решения автора по флажкам не меняет |
| Описать образцы заново | нет | повтор шага `_describe` на готовой системе |
| Удалить | нет | удаление папки системы |
| Повторная загрузка того же pptx | `id` из имени файла, старая система молча стирается (`pipeline.py`) | по умолчанию: новая система с новым `id`, старая с именем и отметками остаётся |

## Связи

- Колода и сессия сцены ссылаются на одну дизайн-систему по `id`.
- Вариант колоды собран из образцов своей системы; образец «не используется» в вариант не попадает (по брифу).
- Живой слайд собирается на образцах той системы, которую спикер выбрал на «Сцене».

## Разделы приложения

Карта версии 2 от 2026-09-24: «Презентации» (главная, генерация, правка), «Дизайн-системы», «Live-режим», настройки «Агенты и модели». Вкладка «Речь» ушла 2026-09-23.

| Что на экране | Сейчас | По брифу |
|---|---|---|
| Недавние презентации на главной | списка нет: только `GET /decks/{id}` | `GET /decks`; название из `plan.title`, дата из `run.json` (`started_at`), число слайдов из плана, первый слайд из `slides/1.png` |
| Запрос с главной | `POST /decks` с `variants=["a"]` по умолчанию | главная просит три варианта: `variants=["a","b","c"]` |
| Объект правки | нет | один вариант колоды; правка пишет новый `deck.json` варианта и заново выпускает pptx, pdf, html и картинки; прежний `deck.json` хранится для «Вернуть как было» |
| Ход генерации | события конвейера: `plan`, `slide`, `audit`, `export-pptx`, `export-html`, `convert`, `render-slides`, `audit-contextual`, `done` | лента: «План» = `plan`; «Вёрстка» = `slide`; «Проверка по правилам шаблона» = `audit`; «Файлы» = `export-*`, `convert`; «Проверка смысла» = `audit-contextual`. Картинка слайда до выпуска pptx: `export/render.py` `render_spec` по одному слайду |
| Описание образцов CLI-агентом | только модель с картинками через OpenAI-совместимый сервер | агент должен принимать картинку; «Проверить» в настройках проверяет и это |

## Агенты и модели (карта версии 2, 2026-09-24)

| Сущность | Что это | Сейчас | По брифу |

| Что | Сейчас | По брифу |
|---|---|---|

| Копия слайда | нет | действие в правке |

| Новые поля дизайн-системы | `DesignSystem` в `contracts.py` отбрасывает незнакомые поля | поля `name`, решения автора по образцам, «снятие подтверждено», «описание пропущено» добавляются в `contracts.py`; «Описать заново» решения автора не трогает |
