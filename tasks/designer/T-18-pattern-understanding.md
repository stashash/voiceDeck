# T-18. Понимание паттернов: связанные группы, заглушки, крупные числа, описание по картинке

Модель: opus. Волна 3. Зависит от слитых T-02, T-04, T-11.

## Цель

Сквозная колода на выданных шаблонах показала, где разбор ошибается. Карточки легли на слайд «команда» с серыми кругами под фото. Шаги в шаблоне Education потеряли связь номеров с подписями: кружки и подписи под ними это две отдельные группы. «Крупного числа» не нашлось ни в одном шаблоне, хотя слайды с «91 %» и «43 %» есть. После этой задачи дизайн-система знает, для какого содержания каждый слайд-образец, и говорит это человеку на странице дизайн-системы одной фразой.

## Что сделать

1. Связанные группы. Две группы одного слайда с одинаковым числом блоков, одним направлением и совпадающими центрами блоков по оси повтора (допуск 0,02) считаются связанными: у каждой в `linked_group_ids` стоит id другой. Главная группа (`primary_group_id`) та, у чьих блоков больше текстовых слотов, при равенстве та, у кого больше площадь блока.
2. Заглушки под фото. Фигура без текста либо с текстом-подсказкой, залитая серым (насыщенность ниже 0,1, яркость от 0,5 до 0,9), круг, овал или скруглённый прямоугольник, стоящая внутри блока или отдельно, это `Area` вида `image` с `placeholder=True`. Картинка с серой заливкой без деталей тоже. У паттерна `needs_images=True`, когда заглушки есть в каждом блоке главной группы либо заглушка занимает больше 15 % слайда. Подсказки вроде «вставить фото» распознавать по общим признакам (короткий текст внутри серой фигуры), а не по словам.
3. Крупное число. Слот с числовым образцом (цифры, знак процента, валюта, до 6 знаков) и кеглем не меньше двух кеглей основного текста слайда получает роль `number`. Паттерн с одним, двумя или тремя такими слотами и малым объёмом прочего текста получает тип `big_number`.
4. Тип «команда»: группа блоков с заглушкой под фото и короткой подписью это `team`, а не `cards`.
5. `describe.py`: `describe_patterns(ds: DesignSystem, pngs: dict[str, bytes], client: LlmClient) -> DesignSystem`. По картинке слайда-образца модель отвечает по схеме: тип из `SlideKind`, назначение одной фразой по-русски, нужны ли свои фото. Ответ модели уточняет `kind` только там, где уверенность разбора ниже 0,7, и всегда заполняет `purpose`. `needs_images` из ответа модели объединяется с геометрическим признаком через «или». Сбой модели на слайде не роняет разбор: паттерн остаётся как был. Параметры запроса в `skill.yaml`, `reasoning_effort: none`, `temperature: 0`. Картинки даёт вызывающий код.

## Готовность

Из каталога `designer`:

```
python -m pytest tests/parse/test_patterns.py tests/parse/test_geometry.py tests/parse/test_describe.py
```

Прежние проверки этих файлов остаются зелёными. Новые проверки на выданных шаблонах (фикстура `templates`):

- «Education», слайды с рядом пронумерованных кружков и подписями под ними (слайды 21, 22, 23): у группы кружков и группы подписей взаимные `linked_group_ids`;
- «VK Tech», слайды-визитки команды (слайды 12 и 13): `needs_images=True`, тип `team`;
- «Education», слайд с «43 %» (слайд 18), и «VK Tech», слайд с «91 %» (слайд 33; если номер не совпал, найти слайд по образцу текста и записать верный номер в тест): тип `big_number`, есть слот с ролью `number`;
- в каждом шаблоне у каждого паттерна с группами стоит `primary_group_id`;
- сторонний pptx разбирается без исключений.

`test_describe.py` без живых вызовов, через `httpx.MockTransport`: ответ модели меняет тип только при низкой уверенности; `purpose` заполняется; сбой сервера оставляет паттерн прежним; картинка уходит в запрос.
