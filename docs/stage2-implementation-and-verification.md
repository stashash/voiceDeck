# Вторая ступень: реализация и воспроизводимая проверка

Источник требований: `Вторая_ступень,_задача__Цифровой_дизайнер_презентаций_ (2).pdf`, предоставленный пользователем; дополнительно — девять сочетаний A/B/C × VK Tech / WorkSpace / Education и видео на незнакомом шаблоне. Предыдущий аудит `stage2-compliance-audit-2026-10-19.md` описывает состояние **до** этих исправлений.

## Что изменилось

| Требование | Реализация и проверяемая граница |
|---|---|
| CSV, XLSX, табличный JSON, текст с таблицей | Семь синтетических файлов; отдельный временной ряд в XLSX, доли в JSON, встроенная таблица в Markdown. Профиль определяется содержимым, а не расширением. |
| Профилирование | Типы, время, размер, измерения/метрики и их количества, пропуски, IQR-выбросы. Кандидаты иерархий — только наблюдаемая функциональная зависимость ребёнок→родитель с повторными наблюдениями, без пропусков и взаимно однозначных псевдоиерархий. Это кандидат по данным, а не утверждение бизнес-семантики. |
| Выбор аналитической задачи | Бриф передаётся планировщику; изменение брифа сбрасывает устаревший результат. Просьба вынести справочник в приложение не превращает все датасеты в таблицы. Несколько разных задач в одном брифе сохраняют индивидуальный подбор по профилям. |
| 2–3 варианта визуализации | Ранжированные кандидаты с выбранными полями, причинами, ограничениями и охватом. Пользователь может поменять вариант до создания презентации. Невозможные/небезопасные варианты не выдаются за доступные. |
| Набор визуализаций | Линия, столбцы, доли, гистограмма с рассчитанными интервалами, scatter с числовой X-осью, grouped/stacked, KPI и таблица. Накопление не предполагает автоматически суммируемость метрик. |
| Заголовки-выводы | Изменение между крайними периодами, процент роста, лидер и доля. Формулы/единицы/охват привязаны к источнику. Модель не переписывает вычисленные факты. Промежуточные колебания не называются непрерывным ростом, корреляция — причинностью. |
| Пропуски | Не заменяются нулями. Неполные пары метрик либо отсутствующая категория приводят к читаемой таблице всех строк, сохраняя известные значения; ноль, пустое значение и исключённая строка различаются. |
| Большой справочник | Краткий обзор в основной истории, все 201 строки на отдельных страницах приложения после основной части; диапазоны и происхождение строк доступны для проверки полноты. |
| Нечитаемые данные | Явное сообщение/безопасная таблица вместо нечитаемого графика; неподдерживаемый формат и опасная агрегация не подменяются выдуманными значениями. |
| Стиль шаблона и брендбука | Цвета/шрифты/поля/сетка, подписи и линии осей, легенда, логотип и охранное поле применяются в Scene, HTML и родном PPTX. По умолчанию приоритет у брендбука; переключение/удаление восстанавливают сохранённые правила шаблона. |
| Источники стиля | JSON, PDF с доступными токенами/текстом, локальный бинарный Figma, ZIP-папки изображений и токенов. Реальные примеры и лицензии: `examples/brandbooks/README.md`. |
| Макеты аналитики | Графики и таблицы не попадают на обложки/финальные слайды ради разнообразия. Сохраняется место под заголовок и диаграмму; учитываются краевые логотипы. Для полностью растрового шаблона создаётся чистая композиция из извлечённых токенов вместо чужого слайда-картинки. |
| Локальная работа | Выбранная модель локальна; Figma worker не обращается к облаку и не исполняет код схемы. Play поставляется с сервисом, встроен в HTML. Зависимости Python закреплены. |
| Отзывчивость | До возврата ID создаётся состояние задачи. События генерации объединяются в последовательные обновления состояния, а не создают сотни параллельных запросов. Вычисленные аналитические слайды не проходят лишнюю модельную перепись. |

## Проверки кода

- Полный Python-прогон: **1318 прошли, 28 пропущены**, `artifacts/stage2-demo/backend-final-tests.xml`. Пропуски видны в отчёте и не считаются подтверждённой функциональностью.
- Frontend: **666 прошли, 18 пропущены**; TypeScript и production-сборка успешны.
- Контейнер приложения собирается через `mvn verify` и production frontend; Designer — из закреплённого списка зависимостей и текущих исходников.
- Round-trip PPTX отдельно проверяет редактируемые данные, линии в цвете акцента, положение легенды, шрифт, логотип и сохранение исходных значений.

## Артефакты приёмочного прогона

Итоговые статусы записывают скрипты, а не этот текст:

- `artifacts/stage2-demo/final-v3/run-manifest.json` — девять сочетаний, ID задач, пути PDF/PPTX/HTML, число слайдов и контрольные листы.
- `artifacts/stage2-demo/delivery-verification.json` — машинная проверка типов визуализаций, происхождения данных, всех 201 строк, пропусков/нулей, единиц, файлов и родных редактируемых графиков.
- `artifacts/stage2-demo/screencast/capture-manifest.json` — реальные действия браузера, таймкоды, импортированные материалы, ошибки и число одновременно выполняемых запросов состояния.
- `artifacts/stage2-demo/screencast/audio/manifest.json` — локальная озвучка, исходный текст, длительность и SHA-256 каждого фрагмента.
- `artifacts/stage2-demo/screencast/edit-manifest.json` — соответствие исходной экранной записи финальному ролику; ускоренное ожидание явно обозначено.
- `artifacts/stage2-demo/figma-browser-verification.json` — реальный импорт бинарного `.fig`, извлечённые роли и отсутствие JS-ошибок.

Отсутствие соответствующего итогового файла или статус, отличный от `passed`, означает незавершённую проверку. Наличие кода/теста не заменяет такой прогон.

## Воспроизведение

1. `docker compose build app designer`, `docker compose up -d`.
2. Открыть `http://localhost:8088`, создать дизайн-систему из PPTX, загрузить пример брендбука, затем текст и семь файлов данных.
3. Проверить профили и кандидатов, создать презентацию, открыть редактор, скачать PDF/PPTX/HTML.
4. Девять сочетаний: `python examples/build-stage2.py --base-url http://127.0.0.1:8090 --content-dir artifacts/stage2-demo/content-v2 --output artifacts/stage2-demo/final-v3 --template <Education.pptx> --template <VKTech.pptx> --template <WorkSpace.pptx>`. Для возобновления передать `--resume-deck <id>` в том же порядке шаблонов: уже созданная задача не генерируется повторно.
5. Экранная запись: `node scripts/record-stage2-demo.cjs` с установленным Playwright/Chrome. Затем `scripts/narrate-stage2-demo.py` в локальном Qwen3-TTS окружении и `scripts/assemble-stage2-screencast.py` с imageio-ffmpeg. Эти окружения и модель — отдельные локальные инструменты записи, не зависимости работающего сервиса.

## Ограничения, которые нельзя скрывать

Произвольный формат не означает любую версию/возможность Figma, OCR сканов PDF или понимание всех естественно-языковых правил брендбука. Показываются действительно извлечённые поля и предупреждения. Иерархии — доказуемые кандидаты, а не онтология компании. Недоказанная суммируемость показателей требует выбора автора. Автоматический визуальный аудит проверяет основную часть и границы справочного приложения; детерминированные проверки покрывают каждый слайд, полный модельный аудит доступен отдельно. Техническая проверка WAV/ASR не означает человеческую оценку качества диктора.
