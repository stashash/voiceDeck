# Аудит

Аудит — часть конвейера, а не внешняя проверка (`designer/src/designer/pipeline.py`
запускает его сразу после сборки сцен). Проверки двух видов:

- **Детерминированные** — на одной и той же сцене всегда дают один и тот же результат:
  реестр `CHECKS` в `audit/deterministic.py`, вход — готовые сцены и дизайн-система, модель
  не зовётся.
- **Контекстные** — про смысл, отвечает модель по картинке слайда или по текстам колоды:
  реестр `CONTEXT_CHECKS` в `audit/contextual.py`, ответ на повторном запуске может
  измениться.

## Детерминированные проверки

20 проверок, `run_checks` сортирует находки по слайду, проверке и элементу и даёт им
стабильный `id`. Столбец «Автопочинка» — по факту наличия чинилки в реестре `_FIXERS`
(`audit/fixes.py`), а не по полю `Finding.fixable`: у трёх проверок (`template.contrast`,
`integrity.placeholder_text`, `density.bullets`) находка помечена `fixable=False`, хотя
`audit/fixes.py` её чинит, — это расхождение в самом коде, не опечатка в этом документе.

| Идентификатор | Что проверяет | Группа | Автопочинка | Тестовый файл |
|---|---|---|---|---|
| `layout.out_of_bounds` | элемент вышел за границы слайда | вёрстка | нет | `designer/tests/audit/test_layout.py` |
| `layout.overlap` | два содержательных блока наложились друг на друга | вёрстка | нет | `designer/tests/audit/test_layout.py` |

| `layout.in_margins` | содержимое зашло в поля дизайн-системы | вёрстка | да, сдвиг к направляющей | `designer/tests/audit/test_layout.py` |

`designer/tests/audit/test_registry.py` проверяет сам реестр, а не отдельную проверку:
идентификаторы уникальны, два прогона `run_checks` на одной сцене дают одинаковый
результат, чистая колода из пяти слайдов даёт пустой список находок.
`designer/tests/audit/test_fixes.py` дополнительно проверяет каждую из восьми
автопочинок и то, что находка контекстной проверки получает `status="skipped"`, а не
исключение.

## Контекстные проверки

11 вопросов, ответ «да» или «нет» с причиной. 9 задаются по картинке одного слайда
(`audit_slide`), 2 — по текстам всей колоды без картинок (`audit_deck`). Автопочинки нет ни
у одной: `audit/fixes.py` для `context.*` не регистрирует чинилку, `apply_fixes` отдаёт
`status="skipped"` с причиной «нет автоматической починки».

| Идентификатор | Вопрос | Уровень | Тестовый файл |
|---|---|---|---|
| `context.title_is_conclusion` | заголовок содержит вывод, а не просто называет тему? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.body_matches_title` | содержимое слайда соответствует заголовку? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.one_sentence` | слайд пересказывается одним предложением? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.facts_in_source` | все цифры и факты со слайда есть в исходных материалах? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.has_content` | на слайде есть содержание, а не только заголовок? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.visuals_on_topic` | картинки и значки относятся к теме слайда? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.no_service_text` | нет служебного мусора: реплик спикера, кусков промпта? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.no_typos` | текст без опечаток? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.table_rows_work` | все строки таблицы и элементы легенды работают на мысль слайда? | слайд | `designer/tests/audit/test_contextual.py` |
| `context.one_language` | вся колода на одном языке? | колода | `designer/tests/audit/test_contextual.py` |
| `context.neighbors_linked` | соседние слайды связаны между собой по логике? | колода | `designer/tests/audit/test_contextual.py` |

Сбой сервера модели (сеть, битый JSON после трёх попыток) не роняет аудит: слайд или
колода получает находку `context.unavailable` — она не входит в реестр `CONTEXT_CHECKS`,
потому что это не вопрос о смысле, а признак того, что ответа не было. Покрыто
`test_server_failure_gives_unavailable_finding_not_exception`
(`designer/tests/audit/test_contextual.py`).

## Сверка с приложением 1 к ТЗ

Приложение 1 («Критерии качества и аудита», `docs/requirements/4. VK Tech.pdf`) даёт 35
пунктов: 24 детерминированных (вёрстка, шаблон, плотность, целостность) и 11 вопросов
валидации контента.

### Вёрстка

| Пункт приложения | Покрыт | Чем |
|---|---|---|
| элемент вышел за границы слайда | да | `layout.out_of_bounds` |
| два блока наложились друг на друга | да | `layout.overlap` |
| текст не поместился в свою рамку | да | `layout.text_overflow` |

| блоки не выровнены по направляющим макета | частично | `layout.off_guides` сверяет только левый край с направляющими `guides_x`; вертикальные направляющие `guides_y` в токенах посчитаны (`parse/tokens.py`), но проверка их не использует |
| контент заходит в поля у краёв | да | `layout.in_margins` |
| картинка растянута, пропорции нарушены | да | `layout.image_aspect` |

### Шаблон

| Пункт приложения | Покрыт | Чем |
|---|---|---|
| шрифт не из шаблона или гарнитур больше двух | да | `template.font` |

Все 5 пунктов покрыты: `density.bullets`, `density.bullet_words`, `density.table`,
`density.series`, `density.fill`.

### Целостность

| Пункт приложения | Покрыт | Чем |
|---|---|---|
| файл не открывается | нет как проверка аудита, закрыто на экспорте | `export/pptx_deck.export_pptx` пересохраняет и заново открывает файл перед возвратом (`Presentation(str(out_path))  # файл обязан открываться заново`) — отказ роняет экспорт, а не превращается в находку |
| остался текст-заглушка | да | `integrity.placeholder_text` |
| пустой слайд или слайд с одним заголовком | да | `integrity.empty` |

| у диаграммы нет подписей осей, единиц или легенды | да | `integrity.chart_labels` |

### Валидация контента

Все 11 вопросов покрыты один в один, формулировки совпадают дословно. Порядок отличается:
в приложении `context.one_language` стоит девятым пунктом, между «текст без опечаток» и
«строки таблицы работают на мысль»; в `CONTEXT_CHECKS` (`audit/contextual.py`) все девять
проверок уровня слайда идут подряд, а обе проверки уровня колоды (`one_language`,
`neighbors_linked`) — следом, потому что `pipeline` прогоняет их отдельным проходом
(`_SLIDE_CHECKS`, `_DECK_CHECKS`).

### Итог

31 пункт из 35 покрыт проверкой реестра, 1 покрыт тем же чеком, что и соседний пункт
(текст обрезан краем), 1 покрыт частично (направляющие только по x), 2 не заведены как
проверки аудита, но закрыты на этапе экспорта, а не оставлены без внимания: файл, который
не открывается, и слайд, отданный растровой картинкой. Дыра — только положение логотипа и
колонтитула: ни разбор, ни аудит его не сверяют.

## Как находки доходят до человека и как он выбирает починку

`pipeline.generate_deck` и `pipeline.apply_fixes` пишут находки в `deck.json` варианта
колоды (`designer/store.save_deck_result`). Клиент читает их через `GET /decks/{id}`
(`DeckStateResponse.findings` на каждый вариант) и следит за ходом сборки через
`GET /decks/{id}/events`. По требованиям экрана «Колода» (`docs/design/ui-requirements.md`,
И-4) находка показана меткой на самом слайде; клик открывает панель находок текущего слайда
с отметками «исправить» и «отклонить» — экран ещё не сдан (`T-15a`, в работе), в текущем
API находки отдаются списком, без геометрии панели.

Починка идёт через `POST /decks/{deck_id}/{вариант}/fix` со списком `finding_ids`
(`DeckFixRequest`) → `pipeline.apply_fixes` → `audit/fixes.apply_fixes`. Для каждой выбранной
находки: если проверка — одна из восьми с автопочинкой, применяется её детерминированное
правило (кегль, цвет, сдвиг, очистка текста) и в отчёте пишется `status="fixed"` с тем, что
изменено по-русски; иначе — `status="skipped"` с причиной. После починки детерминированные
находки считаются заново по обновлённым сценам (`run_checks`), непочиненные контекстные
переносятся как есть — их даёт только модель.

Отдельного действия «отклонить находку навсегда» в текущем коде нет: `Finding` не хранит
статус отклонения, и `store` такого поля не пишет. Находка, которую не выбрали для
починки, остаётся в списке и при следующей сборке аудита может появиться снова. Пункт
«находку можно отклонить: она больше не показывается» из `ui-requirements.md` (И-4) —
требование к экрану `T-15a`, в API и в хранилище колоды оно пока не реализовано.
