# T-26. Вид слайда в браузере: картинка из pptx и текстовый слой поверх

Модель: opus. Волна 5. Зависит от слитых T-08, T-11, T-12, T-13.

## Цель

Живой слайд, собранный сервисом из фрагмента речи, в браузере выглядит бедно: чёрный фон вместо фона шаблона, нет карточек, заголовок пропал, значок наехал на текст. Тот же слайд в pptx выглядит родным для шаблона. Причина: сцена для HTML не несёт геометрию фигур, градиенты, картинки оформления, а встроенный шрифт шаблона в браузер не извлекается. После этой задачи человек видит в предпросмотре, на сцене живого режима и в HTML-файле ровно тот слайд, что откроется в PowerPoint, а текст на нём выделяется и ищется.

## Что сделать

1. `convert.py`: постоянная сессия движка. Для PowerPoint это один долгоживущий дочерний процесс `powershell` без окна, который держит COM-объект и принимает команды по stdin (открыть файл, выгрузить слайд в PNG, закрыть), отвечает строкой JSON. Запуск приложения оплачивается один раз, а не на каждый слайд. Процесс закрывается вместе с сервисом и по простою 5 минут; PowerPoint, запущенный человеком до нас, не закрывается. Для LibreOffice остаётся прежний путь по вызову. Для движка `libreoffice` растеризация PDF в PNG идёт через программу `pdftoppm` (пакет poppler-utils), если она есть в `PATH`; иначе прежнее исключение `ConverterUnavailable`. Интерфейс: `class RenderSession` с методами `png(pptx_path, slide_index, width_px) -> bytes` и `close()`, функция `get_session()`.
2. `render.py`: `render_spec(spec, ds, package_dir, width_px=1600) -> bytes`: собрать pptx из одной инструкции через `export_pptx` во временный каталог и снять картинку слайда через сессию. Кеш на диске в `package_dir/render-cache` по хешу инструкции.
3. `html_image.py`: `slide_html(png: bytes, scene: Scene, ds) -> str` и `render_deck_images(deck, ds, pngs) -> str`. Слайд это картинка на весь кадр и поверх неё текстовый слой: каждый текстовый элемент сцены стоит в своей рамке настоящим текстом с прозрачным цветом (выделяется, ищется, читается с экрана). Листание, полный экран и печать как в `export/html.py`. Внешних ссылок нет, картинки base64.
4. `pipeline.py`: после экспорта pptx картинки слайдов каждого варианта кладутся в `decks/<id>/<вариант>/slides/slide-NNN.png`; `deck.html` собирается из картинок с текстовым слоем, прежний HTML чистой разметкой сохраняется рядом как `deck.markup.html`. `live_slide` возвращает ещё и PNG. Нет доступного движка: остаётся прежний HTML разметкой, событие хода работы сообщает об этом.
5. API: `GET /decks/{id}/{variant}/slides/{n}.png`; состояние колоды несёт адреса картинок; `POST /live/slide` отдаёт `html` с картинкой и текстовым слоем и поле `image_png_base64`. Прежние поля ответа остаются.

## Готовность

Из каталога `designer`:

```
python -m pytest tests/export/test_render.py tests/export/test_html_image.py tests/export/test_convert.py tests/test_pipeline.py tests/api
```

Живой движок в тестах не зовётся: сессия подменяется. Проверки: протокол команд сессии (запрос и разбор ответа, повторный запуск упавшего процесса, закрытие по простою); кеш `render_spec` по хешу инструкции; в `slide_html` есть картинка, текст каждого текстового элемента сцены и нет внешних ссылок; колода кладёт картинки и оба HTML; без движка колода собирается с HTML разметкой; `/live/slide` отдаёт картинку; путь картинки с `..` отклоняется.
