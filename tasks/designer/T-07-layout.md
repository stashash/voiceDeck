# T-07. Вёрстка: подбор паттерна, вместимость, сцена

Модель: opus. Волна 2. Зависит от контрактов, пакета дизайн-системы (T-01, T-02) и общего модуля `designer/src/designer/layout/units.py`.

## Цель

Человек даёт план из десяти слайдов и незнакомый шаблон, а получает для каждого слайда паттерн из этого шаблона и готовую геометрию: три причины легли на карточки, пять шагов на шаги, число на крупное число. Если в образце четыре карточки, а пунктов три, блоки перекладываются по сетке шаблона и ничего не наезжает. Кейсодержатель назвал это главным: умение создавать новые композиции в рамках дизайн-системы важнее точного повтора макетов.

## Что сделать

1. `match.py`: `choose_pattern(intent: SlideIntent, ds: DesignSystem, used: list[str]) -> Pattern`. Оценка кандидата складывается из совпадения `kind`, того, что число пунктов укладывается в `min_units…max_units` группы, наличия области под диаграмму или таблицу, когда они есть в намерении, уверенности `kind_confidence` и штрафа за повтор паттерна, который уже стоит в `used` (особенно подряд). Нет паттерна нужного типа: берётся ближайший по структуре (пункты на карточки, шаги, список), а не первый попавшийся. Для одного и того же входа выбор всегда один и тот же.
2. `capacity.py`: `slot_limits(pattern: Pattern, n_units: int) -> dict[str, int]`: сколько знаков помещается в каждый слот и в слоты блока при `n_units` блоках. Ширина блока после перекладки берётся из `place_units`, вместимость пересчитывается от новой ширины (ширина знака 0,52 кегля, интерлиньяж 1,2). По этим числам скилл T-09 пишет текст.
3. `compose.py`: `compose(intent: SlideIntent, pattern: Pattern, ds: DesignSystem) -> SlideSpec`. Заголовок в слот `title`, `key_message` в `subtitle` или `body`, пункты в `unit_text` по слотам блока (`heading`, `body`, `number`), диаграмма или таблица в подходящую область (`viz_area_id`). Если области нет, под визуализацию отдаётся место группы блоков или самого большого слота `body`. Слоты, для которых нет содержания, получают пустую строку: образцовый текст шаблона на слайде остаться не должен.
4. `scene.py`: `build_scene(spec: SlideSpec, pattern: Pattern, ds: DesignSystem, package_dir: Path) -> Scene`. Фигуры слайда-образца читаются из `source.pptx` пакета через `designer.parse.patterns.flatten_shapes`. Каждая фигура становится `Element` с `source_shape_id`: оформление как есть, слоты с новым текстом, блоки по рамкам из `place_units` и `map_shape_box` (значки и картинки с `keep_size=True`), лишние блоки не попадают в сцену, диаграмма и таблица отдельными элементами. Заливку фигур оформления брать из pptx (сплошной цвет либо средний цвет градиента), фон из `background_asset` и `background_color` паттерна.
5. Авто-уменьшение кегля: если текст не помещается, кегль слота опускается на ступень шкалы `tokens.type_scale`, но не ниже самой мелкой ступени. Что не поместилось и после этого, остаётся как есть: это найдёт аудит.

## Готовность

Из каталога `designer`:

```
python -m pytest tests/layout
```

Тесты на синтетических паттернах проверяют: выбор по типу и по числу пунктов; штраф за повтор; детерминированность; рост вместимости, когда блоков меньше; пустую строку в слотах без содержания. Тесты на выданных шаблонах (фикстура `templates`, пакет собирается через `build_package` во временный каталог) проверяют для каждого из трёх шаблонов и для стороннего файла: план из шести намерений разных типов (титул, три карточки, пять шагов, крупное число, таблица, финал) даёт шесть сцен без исключений; в сценах нет ни одного образцового текста исходного слайда; детерминированный аудит `run_checks` на этих сценах не находит `layout.out_of_bounds` и `layout.overlap` между блоками одной группы.

## Запреты

- Никаких имён шаблонов, макетов, номеров слайдов и текстов-образцов в коде.
- Модели и сеть не использовать: вёрстка детерминированная.
- Полный набор тестов не гонять, только `tests/layout`.
