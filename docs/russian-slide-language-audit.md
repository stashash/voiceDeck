# Язык слайдов: причины, исправление и проверка

Дата: 20 октября 2026. Область: конвейер designer, интерфейс создания и редактор, аналитические подписи и экспорт.

## Что проверено на исходной сдаче

Прочитаны все десять фактически выданных PPTX в `artifacts/stage2-demo/Все презентации`: Education, VK Tech и WorkSpace, каждый A/B/C, и «Сторонний шаблон — демо». Проверялись XML текста слайдов и родных диаграмм, а не только план или настройка языка. Снято доступное только для чтения состояние `/decks/664bf9e00de04590a028a6cb0e2c92a3` на `localhost:8090`.

Воспроизводимые исходные свидетельства: `.codex-build/language-before.json` — имена файлов, все найденные строки с латиницей и их частоты; `.codex-build/language-before-state.json` — состояние API. Наличие латиницы само по себе не считается ошибкой: REF-001, USD, URL, названия брендов, файлов и листов должны сохраняться.

Во всех десяти файлах обнаружились одни и те же группы непереведённых подписей:

- `actual leads`, `target leads`, `channel`, `tickets`, `Requests`, `Region`;
- `Search`, `Social`, `Partners`, `Email`, `Resolved`, `Pending`, `Escalated`, региональные категории;
- шапки справочника, `Reference item 001` и следующие записи, `Week 1`, пояснения пропусков;
- английская проза исходного Markdown в длинной полосе источника.

Первопричины: API и UI не принимали язык; `DeckPlan.language` был необязательной декларацией модели; планировщик и заполнение слотов не получали явного требования; аналитические слайды намеренно обходят модель для защиты чисел, поэтому модель вообще не могла исправить их подписи; старый словарь содержал семь названий полей. HTML и PowerPoint добросовестно экспортировали уже смешанные подписи.

## Как устроено исправление

`POST /decks` принимает `language: "ru" | "en"`, по умолчанию `"ru"`. Другие значения отклоняются. Выбор доступен на главной странице и в форме новой презентации голосовой студии. Язык передаётся планировщику, заполнению слотов, плану, вариантам и последующему переписыванию слайда агентом. При явном игнорировании языка длинной прозы модель получает один повтор; после повторного нарушения генерация плана завершается ошибкой, а заполнение слота использует исходный план.

Новый модуль `designer.localization` создаёт копию отображения:

- локализует известные поля, составные показатели вида actual/target/planned + мера, подписи осей и рядов;
- переводит категории только при известном смысловом поле, например Search в channel, но не Search в company;
- переводит только полные шаблоны текстовых ячеек вроде Week N или Reference item N в соответствующих столбцах;
- сохраняет знаки, разряды, числовые строки, пропуски, нули, порядок строк, категории неизвестного смысла, идентификаторы, имена и URL;
- сохраняет `DataProvenance` целиком, исходные снимки и заметки; на слайд выводит компактные идентификаторы источника и охват из provenance. Длинный исходный контекст остаётся в заметках;
- для английской презентации переводит кодовые аналитические формулировки, включая максимум, долю, динамику, проценты и оговорки. Информативный вывод не заменяется общей фразой о числе строк.

Это ограниченный и проверяемый словарь отображения, а не обещание автоматического перевода произвольного бизнес-текста. Неизвестные английские поля в русской колоде и оставшийся русский текст в английской сохраняются и дают видимое предупреждение `language_unresolved` в проверках слайда. Предупреждение просит подтвердить имя/бренд либо задать проверенный перевод. Нельзя считать всякую латиницу ошибкой или переводить торговое название наугад.

Имена исходных файлов/листов и буквенные обозначения физических/денежных единиц остаются как идентификаторы. Генерируемые словесные единицы «наблюдений» и «шт.» имеют английские эквиваленты observations/pcs; числовой смысл и исходная единица в provenance не меняются.

Экспорт использует единые локализованные chart/table объекты для сцен, SVG/HTML и родных объектов PowerPoint. PDF и изображения получаются из этого PowerPoint штатным конвертером. Для новых данных никаких условий по имени демофайла, dataset ID, пути шаблона или конкретной дизайн-системе не добавлено.

## Уже созданные презентации

В редакторе доступна кнопка «Русские подписи». Она применяет операцию только к текущему варианту:

```http
POST /decks/{deck_id}/{variant}/locale
Content-Type: application/json

{"language":"ru"}
```

Поддерживаемый Python-вызов для обслуживания:

```python
from designer.localization import migrate_deck_locale
report = migrate_deck_locale(deck_id, variant="a", language="ru")
```

Нужен правильный `DESIGNER_DATA_DIR`, запуск рядом с обслуживаемым хранилищем и отсутствие параллельного редактирования через другой процесс. Внутри серверного процесса используется существующая блокировка документа. Нельзя одновременно запускать CLI-миграцию и правки той же колоды через сервер: блокировки межпроцессно не общие.

Операция:

1. Отказывается от колоды с ручной ревизией редактора, чтобы не затереть произвольные правки. Не меняет явно английскую колоду на русскую: её авторская проза требует отдельного перевода; кнопка русских подписей у такой колоды скрыта.
2. Создаёт локализованную копию плана и проверяет `evidence_fingerprint`: provenance, числа/порядок рядов, X/Y, числовые токены таблиц и крупные числа не меняются.
3. Повторно компонует аналитические слайды на тех же паттернах, чтобы русский текст прошёл подгонку размеров. Не вызывает LLM.
4. До сохранения архивирует точный `deck.json`, все `files/` и `slides/` в `locale-backup-*`, а также создаёт обычный снимок истории.
5. Пересчитывает детерминированный аудит и предупреждения языка. Старый визуальный/контекстный аудит изменённых слайдов не переносится как актуальный.
6. Сохраняет новую ревизию и синхронно дожидается экспорта.

Ответ содержит путь архива `backup`, `evidence_sha256`, `numerical_evidence_unchanged`, `language_review_slide_ids`. Узкое исключение из `data_source_edited` применяется только к этой проверенной операции; обычные изменения данных по-прежнему помечаются. Английский перевод произвольной уже написанной русской колоды этой кнопкой не обещается; `"en"` здесь отклоняется. Английский язык выбирается при создании.

Для отката доступны архив и обычная история редактора. Если конвертер недоступен или экспорт упал, архив остаётся; отсутствие свежего PDF/изображений нельзя выдавать за успешную проверку всех форматов.

## Границы доказательства качества

Эти тесты подтверждают код и временный экспорт, но не заменяют проверку актуального развернутого сервиса, живого локального LLM и всех десяти доставляемых PDF/HTML/PPTX. Пересборка runtime, миграция демоколд и проверка их экспортов выполняются отдельно координатором; их результаты должны быть приложены к сдаче. Из этого отчёта нельзя заключать, что эти шаги уже прошли.

Новый детектор заглушек отмечает известные фразы вроде Click to add title и Lorem ipsum. Он не читает текст внутри растрового фона и не доказывает отсутствие любых чужих шаблонных надписей. Геометрические проверки и подгонка шрифта также не доказывают визуальную читаемость: длинные русские подписи и плотное приложение нужно проверить на отрендеренных страницах.
