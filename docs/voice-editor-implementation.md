# Голосовое редактирование: реализация и проверка

Дата: 26 сентября 2026. Рабочий адрес: http://localhost:8088/#/editor.

Это реализованный и проверенный основной поток редактирования, а не обещание полной совместимости с любым PowerPoint. Исходные презентации не перезаписываются при переводе в редактор элементов.

## Что работает

- Точное локальное создание заголовков, текста, карточек, фигур, таблиц; составная команда «Добавь заголовок План запуска и две карточки: Продукт и Продажи» выполняется полностью и отменяется одним действием.
- Выбор по стабильным номерам и тексту, множественный выбор, группы, перемещение, размеры, выравнивание, распределение, слои, удаление, дублирование, перенос между слайдами.
- Шрифт, размер, цвет, жирность, курсив, выравнивание текста, фон, рамка, скругление, поворот, непрозрачность и блокировка объекта.
- Загрузка PNG/JPEG/WebP, поиск изображений; размещение contain/cover. Поиск и генерация не занимают очередь текстового планировщика. Генератор требует отдельного настроенного провайдера.
- Таблицы: правка отдельных ячеек, добавление и удаление строк/столбцов. Простые столбчатые диаграммы с одной серией неотрицательных значений.
- Создание, выбор, дублирование, перемещение и удаление слайдов, заметки, диктовка, undo/redo, экран зрителя.
- Серверные документы SQLite, резервная копия IndexedDB, последовательное автосохранение, проверка ревизии, повтор запроса с тем же request_id после сетевого сбоя. Конфликт не перезаписывает чужие изменения; можно сохранить отдельную копию.
- HTML, JSON и нативный редактируемый PPTX: текст, фигуры, изображения, таблицы и диаграммы остаются отдельными объектами.
- Готовая презентация открывается через «Голосовой редактор» -> выбранная презентация -> «Редактировать все элементы». Создаётся отдельная редактируемая версия; прежний редактор и исходные файлы остаются доступны.

## Защита от зависания

1. Локальные команды не ждут модель. Сложные команды выполняются по очереди, максимум четыре ожидающих запроса; новая команда не отменяет предыдущую молча.
2. Один активный запрос к интерактивной модели на процесс API. Общий серверный deadline 8 секунд, включая JSON repair. Клиентский watchdog 10 секунд завершает ожидание даже у транспорта, игнорирующего AbortSignal.
3. «Стоп» очищает очередь, отменяет HTTP-запрос и посылает отмену на сервер. Поздние ответы не применяются. Отмена HTTP не гарантирует мгновенной остановки вычислений внутри стороннего GPU-сервера.
4. Контекст содержит текущий и явно названные слайды, а не все изображения и весь документ. План отклоняется, если содержимое включённых слайдов или порядок страниц успели измениться. Навигация и выбор сами по себе не уничтожают полезный ответ.
5. Операции применяются атомарно; ошибка откатывает весь план. История ограничена 100 снимками и бюджетом памяти. После перезагрузки восстанавливается документ, но не история undo/redo.
6. ASR не делит монитор с сетевыми эмбеддингами. Один ограниченный исполнитель, не более одного ожидающего вызова; финальное распознавание ждёт максимум 5 секунд. Нативный вызов, игнорирующий прерывание, не создаёт бесконечные потоки. Для восстановления реально зависшего нативного движка может потребоваться перезапуск app.
7. В режиме редактора отключено повторное полное декодирование partial каждые полсекунды; индикатор уровня микрофона остаётся. Команды поступают по окончании фразы. Отключена принудительная 8-секундная нарезка с перекрытием, вызывавшая повтор хвоста команды. При ошибке ASR незавершённый partial не исполняется как команда.

## Запуск

Собранные и запущенные образы: `voicedeck-app:editor`, `voicedeck-designer:editor`.

```powershell
docker compose -f compose.yaml -f compose.editor.yaml up -d --no-build app designer
```

`compose.editor.yaml` меняет только интерактивный маршрут. Для текущей машины проверена уже загруженная Ollama-модель `qwen3.8:27b`, контекст 32768. Модели не скачивались и не выгружались. Остальные назначения агентов не изменены. Порт designer: 8090, приложение: 8088, один worker API.

При пересборке обычный путь: `docker compose -f compose.yaml -f compose.editor.yaml build`. В этой сессии BuildKit завис до сборки, поэтому использован существующий локальный Docker builder:

```powershell
$env:DOCKER_BUILDKIT='0'
docker build --pull=false -t voicedeck-app:editor .
docker build --pull=false -f designer/Dockerfile.code -t voicedeck-designer:editor designer
```

`Dockerfile.code` использует имеющийся `voicedeck-designer:code-base`. Для чистой машины вместо него нужен обычный `designer/Dockerfile`. Legacy builder устаревает; это обход обнаруженного сбоя сборки, не обязательное требование редактора.

Переменные: `DESIGNER_EDITOR_LLM_URL`, `DESIGNER_EDITOR_LLM_MODEL`, `DESIGNER_EDITOR_NUM_CTX`, `DESIGNER_EDITOR_DEADLINE_S`. При пустом editor URL используется локальный live-маршрут; CLI-агенты не запускаются в интерактивном цикле. На момент проверки GPU: 24111 из 24463 MiB занято. Задержки нельзя считать гарантированными при такой конкуренции.

## Команды

```text
Добавь заголовок План запуска и две карточки: Продукт и Продажи
Выбери номера два и три
Вправо на двадцать
Ещё немного
Сгруппируй
Заблокируй
Разблокируй
Добавь таблицу 2 на 2
Ячейка 2, 1: Выручка
Добавь строку
Удали столбец 2
Диктую текст
Управляю слайдом
Отмени
Стоп
Сохрани презентацию
Скачай презентацию
```

Дословный текст с союзами и словами команд лучше задавать в режиме диктовки или кавычках. Неоднозначная сложная фраза отправляется планировщику целиком, а не исполняется частично быстрым парсером.

## Фактическая приёмка

- Frontend: 121 тест прошёл; отдельный live-тест на реальной модели тоже прошёл. В нём 7 команд: создание составного слайда, перемещение плюс стиль, переименование, новый слайд с таблицей, правка цены, удаление на другом слайде, преобразование карточки в текст с заданной геометрией. Время планов: 1.256-5.829 секунды. Это небольшой проверочный корпус, не доказательство p95 полного голосового цикла.
- Java: 87 тестов без ошибок, включая ограниченное ожидание нативного вызова, который игнорирует прерывание. Сборка контейнера выполняет `mvn verify`.
- Python: 458 прошли, 163 пропущены, 3 предупреждения об устаревающих API; счётчики сохранены в `.codex-build/editor-verification/designer-tests.xml`. Часть тестов пропущена из-за отсутствующих исходных шаблонов/внешних конвертеров. Обнаруженное Windows sharing violation при атомарной записи устранено ограниченным повтором; исключения писателя больше не скрываются тестовым потоком.
- Браузер, реальный сервер 8088: compound, локальная правка при зависшем планировщике, отмена позднего ответа, сохранение/перезагрузка, ячейка таблицы и PPTX download. Проверены 1440x1000 и 390x844, горизонтального переполнения нет.
- Реальный PCM через авторизованный WebSocket: 282 подтверждённых пакета, одна финальная фраза, ноль предупреждений, нет непрошеной генерации слайдов. Вход длиной около 9 секунд обрабатывается в реальном времени. Это файл, не тест личного микрофона пользователя.
- Импорт существующей презентации: 15 слайдов, 106 элементов. Оригинал сохранён.
- PPTX открыт повторно библиотекой и отрендерен LibreOffice; проверены отдельные native text/table/chart и заметки. Визуально исправлены унаследованные тени и вертикальное положение текста.

Артефакты: `.codex-build/editor-verification/desktop.png`, `mobile.png`, `editor-smoke.pptx`, `pptx-preview.png`. В серверной библиотеке оставлены явно названные проверочные документы «Проверка голосового редактора».

## Границы

### Исправление неработающих команд, 26 сентября

В открытом редакторе воспроизведён сбой `Выбери заголовок`: команда отправлялась в Ollama и завершалась deadline 8 секунд. `/api/ps` в этот момент возвращал пустой список: прежняя проверка на уже загруженной модели не покрывала холодный запуск.

- Добавлены локальные выбор по типу/порядковому номеру, адресные цвет/размер/перемещение, переименование, фон и переходы между слайдами. Неоднозначный объект не подменяется текущим выделением.
- `POST /editor/intent/prepare` запускает одну общую фоновую загрузку; `GET /editor/intent/model` сообщает её состояние. Загрузка ограничена 60 секундами отдельно от 8-секундного выполнения плана. Локальные команды и отмена работают во время загрузки. Ошибка или смена документа не приводят к позднему применению правки.
- В native Ollama-запросах задан `keep_alive=30m`; модель и контекст не заменены. Механизм использует [Ollama generate](https://docs.ollama.com/api/generate) и [running models](https://docs.ollama.com/api/ps). Новые модели не скачивались.
- На экране отображается последняя распознанная фраза. Так можно отличить ошибку распознавания от ошибки выполнения.
- В живом тесте выявлено пропускание `table_cell.value`: необязательное поле превращалось в пустую ячейку. Для `table_cell` теперь отдельная схема с обязательными `value`, `row`, `column`; непрошеная очистка отклоняется. Исправлены противоречия инструкции о полях таблицы. Уточнение и исполняемые операции нельзя возвращать одновременно.
- Добавлена проверка явно перечисленных числовых свойств (`слева 100, ширина 400`): значения должны присутствовать в исполняемом плане, а не только в summary. Повторная генерация получает конкретную ошибку проверки и остаётся внутри общего deadline. Это узкая проверка буквальных свойств, не полная семантическая верификация всех просьб.

Повторная приёмка: 127 frontend-тестов, 9 целевых backend-тестов. Полный Python-прогон до последней дополнительной проверки числовых свойств: 463 passed, 163 skipped. Итоговый live-сценарий из 7 команд прошёл; 6 запросов к модели занимали 1.269-5.868 секунды, переименование выполнялось локально. Проверены ячейка 900, переход/удаление, преобразование типа и точная геометрия. В действующем браузере проверены выбор заголовка, цвет, составная правка размера/цвета и отмена; тестовые изменения исходного документа отменены. Аудиофайл через реальный WebSocket: 282 подтверждённых пакета, одна финальная фраза, без предупреждений. Личный микрофон пользователя в этой проверке не использовался.

### Замена текста голосом, 26 сентября

В реальных событиях ASR обнаружена форма `Измени текст. Один, два, три...`: пунктуация после команды мешала локальному распознаванию. Также встречались выбор элемента и замена в одной финальной фразе. Общий `textVoice.ts` теперь обслуживает оба редактора, сохраняет регистр и пунктуацию диктовки, распознаёт объединённые фразы и не вызывает модель для буквальной замены.

В редакторе элементов `Измени текст` включает одноразовое ожидание следующей фразы. Она записывается дословно; отмена, смена слайда, выделения или ручная правка защищают от записи не туда. Номер указывает конкретный текстовый объект, даже внутри группы. Распознанная фраза и результат перенесены над холстом.

Приёмка: 143 frontend-теста прошли, один отдельный модельный live-тест пропущен. Включён аудиотест с `EDITOR_TEXT_AUDIO`: синтезированная русская фраза через настоящий авторизованный ASR WebSocket дала `Измени текст` и `Один, два, три`; контроллер заменил старый текст на `Один, два, три` без запросов к модели, подтверждены 182 аудиопакета, предупреждений нет. В браузере проверены объединённая команда и двухшаговая диктовка, изменения отменены и исходный документ сохранён. В редакторе готовой презентации та же команда обновила живой слайд, UI показал 69 мс выполнения (это не задержка ASR); исходный текст восстановлен. Это проверка аудиофайлом, не личным микрофоном пользователя. Посторонние слова внутри одного ASR-сегмента автоматически не отсекаются.

Полный PowerPoint round-trip пока не обеспечен: SmartArt, анимации, сложные эффекты шаблонов, встроенные OLE, посимвольное форматирование, многосерийные/отрицательные диаграммы не покрыты общим редактором. Неподдерживаемые диаграммы при импорте отклоняются явно; исходник не повреждается. Для них остаётся исходный редактор/PowerPoint. Прозрачность и сложное оформление могут отличаться между HTML и PPTX.

Общий p95 «конец речи -> готовая правка» на разнообразной пользовательской речи не измерен. Невозможность зависания любого стороннего GPU/native процесса не обещается: реализованы ограничение ожидания, отмена, защита документа и возможность продолжать локальные правки.
