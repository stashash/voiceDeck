# T-12. Три варианта вёрстки и починка по выбору в сервисе

Модель: sonnet. Волна 4. Зависит от слитого T-13.

## Цель

Человек даёт один бриф и один шаблон и получает три презентации, различимые на глаз и одинаково верные шаблону. Так требует ТЗ: ось различий команда выбирает сама и обосновывает. После аудита человек отмечает находки, которые хочет исправить, и получает обновлённые файлы с отчётом, что изменилось.

- `designer/src/designer/pipeline.py`, `designer/src/designer/store.py`

Модули вёрстки, аудита и экспорта не менять, только звать. `designer.audit.fixes.apply_fixes` пишет параллельная задача T-21: звать её по замороженной сигнатуре из заготовки, в тестах подменять.

## Что сделать

1. `variants.py`: три стратегии над одним планом, каждая это преобразование намерений плюс правило подбора паттерна через параметр `used` у `choose_pattern`:
   - `a` «как в шаблоне»: план как есть, паттерны с точным совпадением числа блоков;
   - `b` «плотнее»: соседние слайды с одной мыслью и малым числом пунктов сводятся в один, слайдов меньше, карточек на слайде больше (в пределах `max_units`);
   - `c` «данные вперёд»: пункты с числами становятся `big_number`, сопоставимые числа идут диаграммой или таблицей раньше текста; паттерны, уже взятые вариантом `a` для того же слайда, штрафуются, чтобы вид отличался.
   `make_variants(plan, ds) -> dict[str, DeckPlan]` и `variant_used_seed(variant, chosen_by_a)`. Обоснование оси одной фразой на вариант лежит в константе и попадает в `run.json`.
2. `pipeline.generate_deck` получает параметр `variants: list[str] = ["a"]`. План строится один раз. Текст под слоты, инструкции, сцены, аудит и файлы по каждому варианту лежат в `decks/<id>/<вариант>/`. Контекстный аудит идёт по первому варианту, по остальным по запросу: иначе три варианта не укладываются в 5 минут.
3. API: `POST /decks` принимает `variants`; `GET /decks/{id}` отдаёт состояние по вариантам; файлы по пути `/decks/{id}/{variant}/files/{name}`; `POST /decks/{id}/{variant}/audit-contextual` запускает контекстный аудит варианта; `POST /decks/{id}/{variant}/fix` с телом `finding_ids` зовёт `apply_fixes`, пересобирает сцены и файлы, отдаёт отчёт и новые находки. Прежние пути без варианта работают для варианта `a`.
4. `python -m designer deck` получает ключ `--variants a,b,c`.

## Готовность

Из каталога `designer`:

```
python -m pytest tests/layout/test_variants.py tests/test_pipeline.py tests/api
```

Живых вызовов нет. Проверки: три варианта одного плана дают разные наборы паттернов либо разное число слайдов; вариант `b` не длиннее `a`; вариант `c` содержит не меньше слайдов `big_number`, `chart`, `table`, чем `a`; генерация с тремя вариантами кладёт три `deck.pptx`, каждый открывается python-pptx; контекстный аудит вызван один раз на колоду; `fix` с подменённой `apply_fixes` пересобирает файлы и отдаёт отчёт; прежние пути без варианта отвечают.
