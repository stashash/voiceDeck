# Большие таблицы: показ, полные данные и качество формирования

## Решение

Большая таблица (>20 строк) по умолчанию занимает один слайд: первые семь строк, явное «фрагмент 7 из 201», предупреждение, что это не репрезентативная выборка, и указание, где все строки. Полный источник остаётся самостоятельной частью поставки. Автор до создания видит два режима и их стоимость: компактный — 1 слайд + полный источник; полный — ceil(N/7) страниц приложения. Предел полного режима — 30 страниц; превышение отклоняется явно, компактный режим не отбрасывает данные. Таблицы 8–20 строк показываются целиком на нескольких страницах; до семи — на одной.

Это способ показа структуры неизвестного источника, не аналитическое резюме. REF-001…REF-201 и вымышленные названия не дают оснований вычислять «инсайты», ранжировать строки или строить диаграмму. Чтобы рассказать содержательную историю о произвольном справочнике, нужны смысл полей и вопрос автора. Слайд с количеством строк как якобы результатом не создаётся. В полном режиме нет дополнительного слайда с тем же количеством.

Цена выбора: компактный PPTX/PDF не содержит все строки на страницах. При пересылке этих файлов нужен архив исходников; рекомендуемый пункт скачивания — полный комплект. HTML самодостаточен: все оригиналы, полный поиск по ячейкам и скачивание работают офлайн, без localhost, CDN или облака. Оригинальные подписи сохраняются в панели источников, даже если слайды локализованы. Показ в PPTX остаётся обычной редактируемой таблицей, а не мелким изображением.

## Подтверждённые родственные дефекты

* Education A: 40 страниц, из них 29 — один источник на 201 строку плюс отдельный слайд «201». Причина — безусловное семистрочное разбиение любой таблицы с добавлением summary. Теперь компактный показ и явный полный режим; summary удалён.
* missing_zero.csv во всех наборах: четыре строки названы «Справочник», а смысл нулей и пропусков потерян. Теперь небольшая таблица не превращается в справочник. Если действительно одновременно есть пустые ячейки и нули, заголовок сообщает проверяемое «Ноль — значение, пропуск — отсутствие данных»; все клетки сохранены. В остальных случаях заголовок нейтрален.
* Education s10 и demo s9/s10: служебная инструкция планировщику («готовые слайды», «слайды уже подготовлены», список технических полей) стала речью для аудитории. Инструкция теперь прямо запрещает такое эхо; планировщик запрашивает исправление и детерминированно убирает оставшееся распознаваемое эхо. Миграция убирает эти обёртки без LLM. Числовые, аналитические и цитатные слайды не проходят этот фильтр. Если удалённая обёртка содержала оговорку о синтетических данных, её точная формулировка переносится на титул. Архив хранит исходную версию целиком.
* Сравнение фактических изображений A/B: 37/40 Education, 38/40 VKTech, 39/40 WorkSpace совпадали. Переименование не исправило бы это. Теперь API сравнивает пиксели актуальных PNG, а интерфейс показывает число совпадений и честное предупреждение при >=80%; полные дубликаты отмечены как копия. Различия не навязываются ценой неверной диаграммы или плохой читаемости. Проверка не утверждает различия, пока экспорт устарел или отсутствует. Это обнаружение ограничений вариантов, а не заявление, что шаблон теперь гарантированно даёт три дизайна.

## Контракты

* `POST /insights/plan/materialize-bundle`: каждая selection может содержать `table_display: "compact" | "full"`; отсутствие означает compact. Выбор независим для каждого dataset. Неверное значение — 422.
* `GET /datasets/{dataset_id}/source`: оригинальные байты, Content-Disposition, X-Source-SHA256. Отсутствующий или повреждённый источник не выдаётся как корректный.
* `DataProvenance.table_display` описывает режим. `row_lines` остаётся полным аналитическим охватом, `displayed_row_lines` — точно видимыми исходными строками (не предполагаются последовательные номера). Строки/значения/пропуски исходного snapshot не меняются.
* Экспорт создаёт `deck.sources.zip`, `deck.bundle.zip`, `sources-manifest.json`. Стандартные `/decks/{id}/{variant}/files/{name}` выдают их как остальные файлы.
* `deck.sources.zip` содержит manifest и для каждого dataset оригинал по `sources/{dataset_id}/original/{filename}` и нормализованную таблицу `sources/{dataset_id}/table.json` с **всеми** строками и номерами. Имена из исходников обезвреживаются для путей, оригинальные байты остаются точными. Manifest содержит original_path/table_path, SHA-256, sheet/table_index/total_rows.
* `deck.bundle.zip`: доступные PPTX/PDF/HTML, архив источников, развёрнутые исходники, manifest и README. PDF включается только если создан конвертером. Самостоятельные PPTX/PDF сопровождаются явно названным архивом, без неработающих локальных гиперссылок. Отдельные файлы допустимо переименовать вместе с соответствующим архивом.
* `designer.export.sources.export_source_package(plan, files_dir)` вызывается после финального HTML/PPTX/PDF при генерации, редакторском экспорте и применении исправлений. Внешние reexport-скрипты должны вызывать его последним. Пропавший или несовпадающий источник блокирует такой экспорт, не выдаёт фиктивную полноту.
* `GET /decks/{id}` возвращает для B/C `comparison_to_a`: basis=exported_pixels, same_pages, total_pages, exact_duplicate, near_duplicate. Сравнение попарное по порядку, а не доказательство семантической уникальности; результаты кэшируются по пути/mtime_ns/размеру изображения.

## Безопасная миграция существующих демонстраций

`designer.reference_display.migrate_deck_reference_display(deck_id, variant="a", mode="compact", export=True)`.

Предварительно требуется внешний snapshot набора и отсутствие параллельного редактирования в другом процессе. Внутри процесса используется обычный lock редактора. Миграция проверяет SHA-256 оригинала и каждую заменяемую отображаемую ячейку относительно локализованного оригинала. Отредактированное доказательство и неполный/фильтрованный источник требуют отдельного разбора: они не восстанавливаются молча. Числовые массивы, таблицы, формулы, source identity и точные plan/spec/scene всех незатронутых слайдов сохраняются. Стабильные id не перенумеровываются. Исходная формула и аналитический охват provenance сохраняются, меняются только режим/страницы/видимые строки.

Сначала создаётся `reference-backup-*` с прежним deck.json, files/, slides/. Новый экспорт готовится во временном каталоге до публикации состояния. Добавляется запись в штатную историю. Устаревшие PNG удалённых страниц удаляются только после создания архива. Отчёт содержит counts, replaced/new ids, removed_instruction_echo_ids, sources, fingerprint незатронутых слайдов, backup и model_calls=0. Повторная миграция в тот же режим не меняет deck. Полный режим восстанавливается из проверенного оригинала; точную предыдущую версию с прежней прозой/экспортами можно восстановить из backup. Вариант `export=False` публикует новую revision; текущие файлы готовятся штатным ensure_export перед скачиванием.

Миграция не вызывается автоматически по всем пользовательским колодам. В этом задании она применена к 12 заранее сохранённым демонстрационным вариантам: три выданных шаблона и сторонний шаблон, A/B/C. В папку выдачи входят девять требуемых презентаций и отдельно вариант A на стороннем шаблоне.

## Проверка

Регрессии проверяют: compact против full; честный 7/201; все 201 строки и точные raw bytes в ZIP и HTML; скачивание оригинала и SHA; ненепрерывные source row_lines; нули/пропуски; RU/EN без изменения evidence; отказ на ошибочном hash; обратимый переход режимов; сохранение остальных chart arrays; archive/history и реальный native PPTX после миграции без модели; повтор без изменений; удаление только распознанного метатекста с сохранением оговорок; пиксельные клоны/изменённые изображения/устаревший экспорт. Реальные десять экспортов, переносимость архивов и визуальную геометрию проверяет runtime-приёмка отдельно.
