# Контраст аналитических диаграмм

20 октября 2026. Исправление после визуальной проверки русифицированной сдачи.

В `artifacts/stage2-demo/russian-localization-visual-grid.jpg` второй ряд grouped-column и сектор Pending в VK Tech сливались с фоном. Причина подтверждена исходными токенами активной дизайн-системы через read-only API: `accent_alt=FFFFFF`, фон слайда `FAFCFF`. Старый `series_colors` выбирал цвет по роли, не проверяя контраст. HTML дополнительно выбирал общую палитру для всех слайдов.

## Исправление

`designer.viz.palette.chart_series_colors(tokens, theme, background, count)` — единый подбор цветов для диаграмм PowerPoint и SVG. Существующий `series_colors` остаётся извлечением исходной палитры и по-прежнему используется таблицами.

Порядок работы:

1. Фактический `SlideSpec.background_color` имеет приоритет над цветом паттерна; HTML использует `Scene.background_color`. Если конкретного сплошного фона нет, используется фоновый токен темы, затем белый/чёрный резерв.
2. Читаемые оригинальные цвета резервируются в прежних позициях. Проверяются контраст к фону не ниже **3:1** и попарное расстояние в OKLab не ниже **0.10**.
3. Неудачные/слишком близкие цвета заменяются производными основного хроматического акцента: сначала вариации светлоты и насыщенности, затем соседние оттенки и более широкие повороты тона. Уже читаемый последующий акцент не вытесняется случайной заменой предыдущего.
4. Подбор детерминирован, кэшируется и не повторяет один цвет циклически при нехватке токенов. При невозможности разместить требуемое число различимых цветов выдаётся явная ошибка с предложением разделить диаграмму.
5. У нативных pie/donut цвет текста числовой подписи выбирается отдельно относительно заливки сектора, не ниже **4.5:1**. Иначе после замены белого сектора тёмным чёрная подпись 250 становилась бы невидимой. Значение, положение, кегль, легенда и оси не меняются.

Геометрия диаграммы, данные, категории, названия рядов, структура легенды и стили осей остаются прежними. Нет условий по template ID, dataset ID или имени файла.

## Проверка

Новый `designer/tests/viz/test_chart_contrast.py` содержит 41 тест: белый, почти белый, тёмный и серый фон; 2/3/5/12 цветов; сохранение читаемых оригиналов; повторное применение; приоритет фактического фона над ошибочным токеном; отдельные палитры двух сцен в одном HTML.

Экспортные тесты сохраняют и открывают PPTX, затем проверяют **активные** XML fill/stroke/marker узлы grouped-column, stacked-column, pie, donut, line и scatter. Проверяются совпадение цветов с SVG, читаемость заливок и числовых подписей, точное сохранение значений и названий рядов, названий осей и переданного ChartSpec. Отдельно проверена передача фона через основной `_fill_viz` экспортера.

Прогоны:

- `designer/tests/viz`, `designer/tests/export`, stage2 charts, localization, reference performance: **224 passed, 8 skipped** до последнего дополнения цвета числовых подписей.
- После дополнения и двух тестов основного экспортера: `designer/tests/viz`, `designer/tests/export/test_svg_chart.py`, stage2 charts, localization — **131 passed**.

Старое ожидание неизменного тёмного `accent_alt` на тёмном фоне заменено проверкой его контраста; читаемые оригинальные акценты остаются проверены явно.

Исходники не перезапускают сервис и не меняют сохранённые колоды. Обновлённый экспорт девяти сдаваемых вариантов и визуальное подтверждение реальных PDF выполняет координатор.

## Ограничения

OKLab-порог — эвристика различимости, а не доказательство доступности для всех нарушений цветового зрения. Растровые и градиентные фоны не анализируются попиксельно: при отсутствии сплошного цвета используется объявленная тема. Для такого шаблона требуется визуальная проверка или отдельная однотонная область диаграммы. Контраст заливки не заменяет проверку размера текста, плотности категорий и качества компоновки.
